# Agently 意图摘要

> 初稿基于 4.1.3.5；训练中逐项验证。

## 1. 它是什么

1. Agently 是 AI 应用运行时框架，中心能力是稳定请求、结构化输出、可观测 Action 和可恢复工作流。
2. 它试图把模型差异隔离在 Provider 插件后，把业务代码稳定在 Prompt、输出契约和执行生命周期之上。
3. 它不是只服务于多智能体聊天的框架，也不是通用容器编排系统。

## 2. 它解决的工程问题

| 问题 | Agently 的答案 |
|------|----------------|
| 模型输出漂移 | schema、parser、ensure、validate、retry |
| 切换模型供应商 | `ModelRequester` 插件 |
| 模型调用工具 | Action Registry、Runtime、Executor |
| 工具依赖长期资源 | Execution Environment Provider |
| 复杂流程 | TriggerFlow、Dynamic Task |
| 多轮上下文 | Session、Recall、Workspace |
| 调试困难 | EventCenter、RunContext、DevTools |

## 3. 最小运行单位

`ModelRequest` 是最小模型请求单位；`AgentTurn` 是 Agent 上的一次请求草稿；Agent execution 为其增加编排和能力执行。

## 4. 三条边界

- Request 负责一次模型调用、结构化解析和校验。
- Action Runtime 负责一次请求内的能力规划、分发与日志。
- TriggerFlow 负责请求外的分支、并发、暂停恢复和持久化。

## 5. 生态关系

```text
Application
  |
Agent Extensions / facade
  |
Core contracts
  |
Plugins and providers
  |
Model API / MCP / sandbox / browser / database
```

## 6. 不适用场景

- 只有一两个简单提示词且不需要结构化约束。
- 只需要供应商 SDK 的原生能力。
- 需要完整分布式任务调度平台，而不是进程内 AI workflow。
