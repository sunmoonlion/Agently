# Agently 源码阅读训练计划

> 42 天，建议每天 1.5-3 小时。天数是步骤标签，不是进度压力。

## 使用规则

每一天都完成：

1. **Task 1 读**：按指定范围阅读。
2. **Task 2 练**：完成可验证的定位、画图、跟栈或编码。
3. **Task 3 整理**：更新交付物和读码日志。

没有完成 Task 2 的证据，不算完成当天训练。

## 阶段 1：意图层

### Day 1：根 README

- 读：Who、Why、Positioning、Quickstart。
- 练：闭卷回答框架是什么、不是什么。
- 限制：不读实现。
- 写入：`01-意图摘要.md` 第 1、2 节。

### Day 2：能力地图

- 读：README Core Capabilities。
- 练：把能力归入 Request、Action、Orchestration、Session、Observation。
- 写入：`01` 第 2、3 节。

### Day 3：中文 overview 对照

- 读：`docs/cn/requests/overview.md`、`actions/overview.md`、`triggerflow/overview.md`。
- 练：找出三层边界，各写一个不适用场景。
- 写入：`01` 第 4、6 节。

### Day 4：架构声明与闭卷口述

- 读：`docs/cn/architecture/extension-boundaries.md`。
- 练：5 分钟口述；完成“我不读清单”。
- 验收：Request、Action、Environment、TriggerFlow 不混淆。

## 阶段 2：边界层

### Day 5：包与依赖

- 读：`pyproject.toml`、两层目录树。
- 练：不看实现，为每个顶层包写一句职责。
- 写入：`03-边界地图.md`。

### Day 6：公开入口

- 读：`agently/__init__.py`、`agently/core/__init__.py`。
- 练：随机定位 10 个公开符号。
- 限制：每个定义只看类声明附近。

### Day 7：全局装配

- 读：`agently/base.py` 初始化区、`_default_init.py`。
- 练：画 import 时对象图和默认插件表。
- 写入：`03`、`05` 初稿。

### Day 8：边界闭卷

- 练：15 分钟回答“新增模型、新 Action 后端、新环境、新 Agent helper 分别改哪里”。
- 验收：路径和 plugin type 至少 80% 正确。

## 阶段 3：契约层

### Day 9：Agent 与 AgentTurn

- 先读测试和 quick prompt 调用点，再读 `Agent.py`、`AgentTurn.py`。
- 练：区分 Agent 级状态与 turn 级状态。
- 写入：`04-契约卡片/AgentTurn.md`。

### Day 10：Prompt

- 读：Prompt 公开方法和 PromptGenerator 测试。
- 练：追踪一个 output schema 的三种表示。
- 写入：`Prompt.md`。

### Day 11：ModelRequest

- 读：`ModelRequest.py` 与 request tests。
- 练：列出 parent settings、prompt、handlers 的继承关系。

### Day 12：ModelResponse

- 读：`ModelResponse.py` 构造和 generator 主干。
- 练：证明快照边界，记录 RunContext 层级。

### Day 13：ModelResponseResult

- 读：结果读取 API 和 validate tests。
- 练：画 text、data、meta、stream 的共享消费关系。
- 写入：`ModelRequest-Response.md`。

### Day 14：Action

- 读：ActionRegistry、Dispatcher 和 Action facade。
- 练：注册最小本地函数 Action。
- 写入：`Action.md`。

### Day 15：Execution Environment

- 读：Manager、Provider protocol 和一个 MCP 或 Python provider。
- 练：列出资源从 require 到 release 的状态。
- 补充：`Action.md`。

### Day 16：TriggerFlow 契约

- 从 contract、state、pause/resume tests 反推。
- 练：区分 definition、execution、state、resource、stream。
- 写入：`TriggerFlow.md`。

## 阶段 4：组装层

### Day 17：AgentlyMain

- 读：`base.py` 的 factory 和 facade。
- 练：从 `Agently.create_agent()` 画出对象图。

### Day 18：Agent extensions

- 抽样：ActionExtension、SessionExtension、ConfigurePromptExtension。
- 练：判断每个 helper 应属于 extension、plugin 还是 core。

### Day 19：PluginManager

- 读：register、activate、schema registration。
- 练：写最小假插件并注册，不发网络请求。

### Day 20：组装闭卷

- 练：解释 eager registration、lazy provider construction 和 response snapshot。
- 定稿：`05-组装流程图.md`。

## 阶段 5：执行层

### Day 21：请求链入口

- 从 `agent.input(...).output(...).start()` 开始。
- 练：只用 `rg` 找到前四跳。

### Day 22：Agent execution

- 读：默认 AgentOrchestrator 的 one-turn 路径。
- 练：标出 execution stage 与 request 创建点。

### Day 23：Provider 请求

- 读：ModelResponse 到 OpenAICompatible 的边界。
- 练：记录标准 Prompt 到 provider payload 的形变。

### Day 24：响应与流

- 读：Provider stream 到 ModelResponseResult。
- 练：记录消息类型与事件类型。

### Day 25：解析与校验

- 读：ResponseParser 和 validate/repair tests。
- 练：构造缺字段响应，确认 retry 或 failure 路径。

### Day 26：请求链复述

- 定稿：`chain-a-structured-request.md`，补文件和行号。
- 验收：60 分钟内完整跟链，迷路不超过 3 次。

### Day 27：Action 链

- 跟踪：注册 -> Runtime -> Dispatcher -> Executor -> ActionResult。
- 写入：`chain-b-agent-action.md`。

### Day 28：Action 失败链

- 练：让本地 Action 主动失败，定位错误归一化与日志。
- 验收：能从 observation 定位失败阶段。

## 阶段 6：扩展层

### Day 29：OpenAICompatible

- 对照 ModelRequester 契约标注实现职责。
- 写入：`07-集成对照表.md`。

### Day 30：Anthropic 对照

- 只读与 OpenAI 不同的路径。
- 练：列出相同 Core 输出如何吸收协议差异。

### Day 31：ActionExecutor 对照

- 对比 LocalFunction、MCP、PythonSandbox。
- 练：判断何时需要新 Executor。

### Day 32：Environment Provider 对照

- 对比无环境 Action 与 MCP/Python 环境。
- 练：判断何时需要新 Provider。

### Day 33：最小扩展

- 实现一个无网络的最小 plugin 或 Action。
- 添加针对性测试。
- 验收：不修改无关 Core 文件。

## 阶段 7：设计层

### Day 34：请求快照

- 完成 `08/01-为什么请求快照.md`。
- 要求：至少一个测试证据。

### Day 35：Action 与环境

- 完成 `08/02-Action与环境为何分离.md`。
- 要求：对比两个不同 executor。

### Day 36：TriggerFlow

- 读最小 execution 主链和事件测试。
- 完成 `08/03-为什么TriggerFlow不是普通DAG.md`。

### Day 37：兼容策略

- 搜索 deprecation、legacy、compatibility。
- 练：选一个旧 API，解释保留成本和迁移路径。

### Day 38：版本演进

- 抽样 4.1.3.x release notes。
- 练：找出一次契约收紧及其测试变化。

## 阶段 8：验收

### Day 39：反向工程 1

- 只看需求：“增加一种模型 Provider”。
- 先预测文件、类、方法，再读码验证。

### Day 40：反向工程 2

- 只看需求：“增加需要长期浏览器会话的 Action”。
- 预测 Action、Executor、Environment、Agent helper 的分工。

### Day 41：TriggerFlow 调用链

- 完成 `chain-c-triggerflow.md`。
- 不要求读完 Execution，只跟最小 happy path。

### Day 42：毕业验收

- 30 分钟闭卷画地图。
- 15 分钟定位一个陌生扩展点。
- 60 分钟跟完一条随机主链。
- 90 分钟完成最小改动和测试。
- 定稿：`00-我的框架阅读方法论.md`。
